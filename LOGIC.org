* PHASE 1: Locate and Verify
Read ~/.mozilla/firefox/profiles.ini to find the active profile directory. Check for the presence of lock or .parentlock files in that directory; if they exist, Firefox is running, and the program must safely exit to avoid corrupting data.

* PHASE 2: Move to RAM
Move the entire profile directory to a tmpfs location. While /tmp works, /dev/shm or your user's $XDG_RUNTIME_DIR (usually /run/user/1000/) are the standard locations for this.

* PHASE 3: Bridge with a Symlink
Create a symbolic link at the original ~/.mozilla/firefox/your_profile.default location that points to the new directory in /dev/shm. Now, when you open Firefox, it follows the symlink and performs all its heavy I/O operations entirely in RAM.

* PHASE 4: Sync Loop
The Rust program enters a sleep loop. Every hour (or whatever interval you choose), it uses the system's rsync command to copy the data from RAM back to a backup folder on your physical disk.

* PHASE 5: Graceful Shutdown
When runit tells the daemon to stop (e.g., when you shutdown the laptop), your program catches the termination signal, does one final rsync to save your data, deletes the symlink, and moves the profile folder from RAM back to its original physical location.
